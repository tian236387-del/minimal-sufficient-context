# MSC V0.2 真人实验

这套工具用于收集真实参与者在编程、研究、写作多分支任务中的表现。它不会生成或补写参与者结果；当前只有真实完成并落盘的会话才会进入分析。

## 实验设计

- 被试内交叉设计：每人完成 6 题，三个领域各完成一次 `Linear` 和一次 `Branch`。
- 12 个平衡单元：六种领域顺序乘以两种起始条件；服务端优先分配当前样本最少的单元。
- 每个领域有 A/B 两套不同场景，避免同一事实包在两种条件间产生直接记忆迁移。
- 模型、温度、上下文窗口和任务文件在同一批实验期间保持固定。
- 每题至少生成一份 AI 草稿后才能提交，避免把纯阅读任务混入模型辅助任务。
- 主指标：目标事实覆盖率、兄弟分支串线率。
- 次指标：活动耗时、信心、工作负荷、上下文易用性、答案信任和条件偏好。
- 自动关键词只做筛查。正式质量结论还需要两名不知道条件的人工评分者按 `tasks.json` 中的 rubric 独立评分。

建议先完成 `n=24` 的可用性试点（每个平衡单元至少 2 人），修订协议后冻结任务，再以 `n=48` 作为第一轮对外验证目标。编程、研究、写作背景参与者应尽量均衡招募。

## 启动

先确认 Ollama 和指定模型已就绪：

```powershell
python -B First/validation/human_study/study_server.py --check
ollama list
python -B First/validation/human_study/study_server.py --model qwen3:4b
```

本机参与者打开 `http://127.0.0.1:8765`。也可以双击 `run_human_study.bat`。

局域网招募可增加 `--host 0.0.0.0`，并把本机局域网地址发给参与者。该服务没有公网身份认证，不要直接暴露到互联网；局域网实验应配合防火墙限制来源。

实验时不要并行下载模型或运行大矩阵，以免系统负载改变任务延迟。若改用其他模型，整批参与者必须使用同一模型参数。

## 数据

服务端只分配随机会话 ID，不请求姓名、邮箱或 IP。参与者仍可能在自由文本中主动写入个人信息，组织者应在导出前检查并脱敏。

- `data/sessions.jsonl`：同意、匿名背景和分配单元。
- `data/events.jsonl`：页面事件、模型提示、模型草稿和延迟。
- `data/results.jsonl`：最终答案、计时、评分和自动串线检查。
- `data/completions.jsonl`：最终偏好与开放反馈。

这些 JSONL 文件已被 `.gitignore` 排除。备份时应加密，并按照参与者告知的保留周期删除。
会话和结果同时记录任务包 SHA-256、模型 digest 与推理参数；分析中的 `protocol_consistent` 必须为 `true`。

## 分析

```powershell
python -B First/validation/human_study/analyze_study.py
```

分析结果写入 `human_study/analysis/`：

- `report.md` / `report.json`：条件汇总、Wilson 区间和配对差异。
- `task_metrics.csv`：不含答案正文的任务级指标。
- `paired_deltas.csv`：每位参与者、每个领域的 `Branch - Linear` 差值。

配对区间按参与者聚类自助抽样，避免把同一人的三组领域结果当成完全独立样本。未完成会话保留用于流失分析，但不会形成完整的被试内配对。

## 执行边界

- 在招募前冻结 `tasks.json`、模型标签和推理参数，并记录文件哈希。
- 试点期间记录中断、模型错误和明显低投入会话，不静默删除；排除规则应先写入研究记录。
- 单题活动时间低于 90 秒、空泛答案或模型失败应标记复核，而不是自动判为无效。
- 未达到预定样本前只报告描述性结果，不把趋势写成产品有效性结论。
